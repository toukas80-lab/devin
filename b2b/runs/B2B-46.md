# B2B-46 — Αρχείο XXF συνημμένο στο email παραγγελίας

Branch `b2b-46` σε worktree `..\devin-b2b46` (από `origin/b2b-45`,
με `b2b/xxf` από `origin/b2b-45-ref`). Χωρίς upload, χωρίς run_sync.ps1,
SQL μόνο read-only (1001).

## Αλλαγές

- `b2b/xxf/template_7021.XXF` → `git mv` σε `b2b/portal/app/xxf_template_7021.XXF`
  (path διορθώθηκε και στο `mk_ref.py`).
- **ΝΕΟ `app/xxf.php`** — `order_xxf(array $o, array $cust, array $lines): string`.
  Πιστή μεταφορά του `xsf_ref.py`/`mk_ref.py`: διαβάζει το template, κρατά τα
  raw bytes της 1ης γραμμής κάθε πίνακα και κωδικοποιεί μόνο τα πεδία που
  αλλάζει το README («What changes per order»): FINDOC (TRDR/TRDR_CODE,
  TRNDATE/BGDOCDATE/INSDATEN=ημ/νία, APPRVDATE/BGDOCDATE1/INSDATE/SOTIME/UPDDATE=
  ημ/νία+ώρα παραγγελίας, FISCPRD/PERIOD, COMMENTS='B2B W-…', REMARKS='W-…',
  PAYMENT από καρτέλα, SERIESNUM=0, FINCODE/TAXSERIESNUM/POSGUID/SHIPMENT=NULL,
  ISPRINT=0, TURNOVR*/NETAMNT*=net, VATAMNT*=vat, SUMAMNT*=net+vat),
  MTRDOC (QTY=QTY1=Σqty), MTRLINES (μία γραμμή/είδος από το template row 1),
  VATANAL (μία γραμμή/κωδικό ΦΠΑ), FINPAYTERMS/SNLINES/FPAYTRMS2/EXPANAL/
  ABCTRNLINES άδειοι. Datetime = double ms (toordinal×86400000 + ms ημέρας,
  ώρα Ελλάδας). RuntimeException αν λείπει vat_code/mtrunit.
  Φορτώνεται από `bootstrap.php`.
- **`helpers.php`**: νέα `send_mail_att()` — multipart/mixed (text/plain UTF-8
  base64 + application/octet-stream base64 chunked), ίδιο From. Το `send_mail`
  άθικτο.
- **`pages.php` `page_order` POST**: το SELECT παίρνει και `i.vat_code,
  i.mtrunit`. Το mail ειδοποίησης τυλίχθηκε σε try/catch: `send_mail_att` με
  `"$orderNo.XXF"` από `order_xxf()` (payment από `customers.payment`,
  created_at από τη γραμμή orders). Σε αποτυχία: error_log + απλό email με
  σημείωση — η παραγγελία δεν αποτυγχάνει ποτέ λόγω XXF. Το email
  επιβεβαίωσης πελάτη έμεινε ακριβώς ίδιο, χωρίς συνημμένο.
- **Schema**: `migrations/016.sql` + `schema.sql` — `customers.payment INT NULL`,
  `items.vat_code INT NULL`, `items.mtrunit INT NULL`.
- **`api.php`**: στο $map → items +`vat_code`,`mtrunit`, customers +`payment`.
- **`sync/export.py`**: Q_ITEMS +`m.VAT AS vat_code, m.MTRUNIT1 AS mtrunit`,
  Q_CUSTOMERS +`t.PAYMENT AS payment`. Το `upload.py` ποστάρει το JSON ως έχει
  και το api κρατά τα mapped πεδία — η ροή είναι πλήρης (export→out→upload→db).
- **ΝΕΑ** `b2b/xxf/test_xxf.php` (δομημένο XXF για τα δεδομένα του template)
  και `b2b/xxf/cmp_ref.py` (σύγκριση ανά πεδίο μέσω xsf_ref, επιτρεπτές
  διαφορές μόνο SOTIME/UPDDATE/APPRVDATE/INSDATE/BGDOCDATE1).

## Έλεγχος/τεστ (βήμα 9)

Δεν υπάρχει php στο μηχάνημα → `test_xxf.php`/`cmp_ref.py` γράφτηκαν αλλά δεν
εκτελέστηκαν. **Αντ' αυτού**: η λογική του `order_xxf` υλοποιήθηκε 1:1 και σε
Python (ίδιος κώδικας raw-segment) και τρέχτηκε με τα δεδομένα του template —
το αποτέλεσμα είναι **byte-identical** με το `xxf_template_7021.XXF` εκτός από
SOTIME/UPDDATE (12:53:09→12:52:28, επιτρεπτό — το PHP τα θέτει από created_at).
`cmp_ref.py php_sim.XXF` → PASS (SOTIME, UPDDATE allowed). Το `mk_ref.py`
επαληθεύτηκε ότι παράγει byte-for-byte το template.
