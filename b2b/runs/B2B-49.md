# B2B-49 — Αυτόματη κατάσταση παραγγελιών πύλης από το SoftOne

Worktree `..\devin-b2b49` (branch `b2b-49` από `origin/b2b-48`).

Κανόνας: ΠΑΡ σειράς 7021 με `FINDOC.COMMENTS = 'B2B W-######'` →
το XXF (`xxf.php`) ήδη γράφει `COMMENTS='B2B '+order_no` και
`REMARKS=order_no`. Βρέθηκε στο SoftOne → `seen` («Σε εξέλιξη»),
`FULLYTRANSF=1` → `done` («Ολοκληρώθηκε»). Μόνο προς τα εμπρός:
new→seen, new→done, seen→done — ποτέ από done/cancelled, ποτέ πίσω.

## Αλλαγές

### `b2b/sync/export.py`
- Νέο `Q_ORDER_STATUS`: FINDOC με `COMPANY=1001, SOSOURCE=1351, SERIES=7021,
  ISCANCEL=0, TRNDATE>='2026-10-14', COMMENTS LIKE 'B2B W-%'`
  → `comments, fincode, fullytransf`.
- Νέα `order_status_rows(raw)`: regex `W-\d{6}` στο comment → `order_no`;
  πολλά FINDOC ανά order_no κάνουν merge — `done=1` αν έστω ένα έχει
  `FULLYTRANSF=1`, `fincode` = του τελευταίου μη-κενού.
- `main()`: `dump("order_status", …)` μετά τα invoices
  → `b2b/out/order_status.json` `[{order_no, fincode, done}]`.

### `b2b/sync/upload.py`
- `"order_status"` τελευταίο στο `DATASETS` (file `order_status.json`).

### `b2b/portal/app/helpers.php`
- Νέα `status_mail(array $o, string $status)`: το ίδιο email που έστελνε
  το `admin_status` (ίδιο θέμα `Παραγγελία <no>: <status_label>`, ίδιο
  κείμενο, ίδιοι έλεγχοι email — κενό/μη έγκυρο → δεν στέλνει).

### `b2b/portal/app/admin.php`
- `admin_status` καλεί `status_mail($o, $status)` αντί για `send_mail`
  (ίδιες εξωτερικές συνθήκες, ίδιο flash). Καμία άλλη αλλαγή.

### `b2b/portal/app/api.php`
- `api_sync`: αν `dataset=order_status` → `api_order_status()` **πριν**
  το `$map` (κληρονομεί ίδιο POST-check, auth, JSON header).
- Νέα `api_order_status()`: ίδια gzip+json αποκωδικοποίηση και
  `{"error":…}` χειρισμός με τα άλλα datasets. ΧΩΡΙΣ DELETE.
  Ανά γραμμή `{order_no, done}`:
  - `done=1` → `UPDATE orders SET status='done'
    WHERE order_no=? AND status IN ('new','seen')`
  - `done=0` → `UPDATE orders SET status='seen'
    WHERE order_no=? AND status='new'`
  - `rowCount()===1` → διαβάζει `order_no/total/created_at` + `c.email`
    και `status_mail()`.
  - `sync_log` με `dataset='order_status'`, `row_count=changed`.
  - Απάντηση `{"ok":true,"rows":N,"changed":M}`.

## Βήμα 5 — Έξοδος Q_ORDER_STATUS (read-only, 1001)

```
(0 rows affected)
```

Κανένα FINDOC δεν έχει ακόμα `COMMENTS LIKE 'B2B W-%'`: η W-000007
(FINDOC 255056 του B2B-44) έχει αντικατασταθεί — η ΠΑΡ0000888 είναι πάλι
το παλιό `FINDOC 215671` (TRNDATE 2025-12-01, FULLYTRANSF=1, COMMENTS
NULL), και έλεγχος σε `COMMENTS`/`REMARKS LIKE '%W-000%'` σε όλη την
1001 βγάζει 0. **Σημαντικό:** η αλυσίδα θα δουλέψει μόνο αν η εισαγωγή
XXF στο SoftOne κρατήσει το `COMMENTS='B2B W-…'` — στο test import της
ΠΑΡ0000888 το πεδίο δεν επιβίωσε (το παραστατικό ξαναγράφτηκε). Να
επαληθευθεί με την πρώτη πραγματική παραγγελία.
