# B2B-22b — Έλεγχος scheduled task sync (ΜΟΝΟ ΕΛΕΓΧΟΣ)

Καμία αλλαγή σε Windows ή κώδικα.

## 1. Scheduled task «B2B Sync»

| Ρύθμιση | Τιμή |
|---|---|
| Principal UserId | `User` |
| LogonType | **Interactive** |
| RunLevel | Limited (χωρίς elevation) |
| ExecutionTimeLimit | PT72H (3 ημέρες) |
| StartWhenAvailable | **False** |
| WakeToRun | **False** |
| DisallowStartIfOnBatteries | True |
| StopIfGoingOnBatteries | True |
| MultipleInstancesPolicy | (προεπιλογή) |
| Trigger | Enabled, StartBoundary 2026-10-11T07:00:00, επανάληψη κάθε **PT30M** για **PT14H** (δηλ. ~07:00–21:00) |
| Action | `powershell.exe -NoProfile -ExecutionPolicy Bypass -WindowStyle Hidden -File …\b2b\sync\run_sync.ps1` |

## 2. Πηγή SQLCMDPASSWORD

- `export.py` το διαβάζει από `os.environ['SQLCMDPASSWORD']` (γραμμή 21· αν λείπει, exit στη 257-258).
- Η μεταβλητή είναι ορισμένη σε επίπεδο **User** (user environment variable του χρήστη `User`). Σε επίπεδο Machine **δεν** είναι ορισμένη. Δεν διαβάζεται από αρχείο.
- Επειδή το task τρέχει Interactive ως ο ίδιος χρήστης, κληρονομεί το user env και τη βρίσκει.

## 3. Ρυθμίσεις ύπνου (powercfg SCHEME_CURRENT)

| Ρύθμιση | AC | DC |
|---|---|---|
| STANDBYIDLE | `0x0` → **ποτέ** | `0x0` → **ποτέ** |
| HIBERNATEIDLE | `0x0` → **ποτέ** | `0x0` → **ποτέ** |

Το PC δεν κοιμάται/δεν κάνει hibernate αυτόματα (σε ρεύμα ή μπαταρία).

## 4. Τι συμβαίνει σε κάθε περίπτωση

**(α) Αποσύνδεση χρήστη (logoff):** το sync **σταματά**. Το LogonType
είναι Interactive → το task τρέχει μόνο όσο ο `User` είναι συνδεδεμένος.
Κατά το logoff τερματίζεται και όποια εκτέλεση είναι σε εξέλιξη. Μέχρι
τον επόμενο logon δεν γίνεται συγχρονισμός.

**(β) Κλείδωμα οθόνης (lock):** το sync **συνεχίζει κανονικά** — η
συνεδρία παραμένει logged-on και το Interactive task τρέχει σε κρυφό
παράθυρο. (Σημ.: το πρόσφατο `0xC000013A` = Ctrl+C/τερματισμός κονσόλας
— πιθανή αιτία logoff ή κλείσιμο παράθυρου, όχι σφάλμα κώδικα.)

**(γ) Ύπνος:** στην πράξη **δεν συμβαίνει** — STANDBYIDLE/HIBERNATEIDLE
είναι 0 (ποτέ). Αν το μηχάνημα τεθεί σε ύπνο χειροκίνητα: το task δεν
τρέχει όσο κοιμάται, δεν θα το ξυπνήσει (WakeToRun=False) και η
χαμένη εκτέλεση **δεν** προσπαθείται εκ νέου (StartWhenAvailable=False)
· συνεχίζει από τον επόμενο προγραμματισμένο trigger μετά την αφύπνιση.

**Παράπλευρο ρίσκο:** `StopIfGoingOnBatteries=True` — αν το μηχάνημα
έχει μπαταρία (laptop/UPS) και πέσει το ρεύμα, το sync σταματά στη
μπαταρία. `MultipleInstancesPolicy` default → ταυτόχρονη εκτέλεση με το
χειροκίνητο upload.py μπορεί να επικαλύψει scheduled run (όπως έγινε
στις 15:00 της 11/10 — η παράλληλη εκτέλεση σκοτώθηκε με 0xC000013A).
